# PRD 版本迭代流程

本项目的 PRD 是单文件长文档（2300+ 行），已迭代到 v2.16。每轮改动都走同一套流程，
核心目的是**避免"编辑返回成功但内容没落表"**（本项目已复现多次）。

> **纯实现缺陷（bug）也要走同一套流程**：PRD 是唯一权威文档，实现侧的修正必须在 PRD 里留痕
> （新增 `C<序号>` 写清 **根因 + 修法 + 落点**），版本号与文件名同样递增。做法与功能改动一致，
> 只是落点通常更少（变更记录 + 对应功能章节 + 相关 A 验收项 + 版本行）。

## 硬约束

1. **`.md` 必须保持 UTF-8 无 BOM + LF**；**含中文的 `.ps1` 必须带 UTF-8 BOM**（PS 5.1 否则按 ANSI 解码，会报大量虚假语法错误）。
2. **每轮改动都要：递增文档版本号 + 重命名文件（`git mv`）**，两者必须一致（C37 已定案）。
3. **每次改完必须 grep 复核锚点**，不能只信编辑返回成功。

## 标准流程

### 第 1 步：定位锚点（最易出错）

- **禁止**用 `| C39 | **…` 这类**行首前缀**作 `old_string` —— 会把表格行标签吞掉，导致该行文本悬挂到上一行（本项目已犯两次）。
- 正确做法：用**行中段的唯一片段**（如 `· 离线 · Go · **Win7 SP1+ 兼容**`），或用**完整整行**。
- 插入新表格行时，用**下一行作为锚点**在其前插入，最稳：
  ```
  old: "### 1.2 已决策事项（评审确认，不再作为待确认项）"
  new: "| C41 | …新行… |\n\n### 1.2 已决策事项（评审确认，不再作为待确认项）"
  ```
- 需要**调整行顺序**时，不要靠编辑；用 PowerShell 读入 → 交换数组下标 → 写回（保持 UTF-8 无 BOM + LF）。

### 第 2 步：改正文 + 同步落点

一份改动通常要同步落到**多处**，漏一处就会出现文档自相矛盾：

| 落点 | 说明 |
|------|------|
| 文档信息表版本行 | `\| 版本 \| vX.Y（…特性摘要…） \|` 追加摘要片段（用**行中段唯一片段**改，别动 `\| 版本 \|` 标签） |
| 1.1 变更记录 | 新增 `C<下一个序号>` 行，写清「改了什么 + 为什么改」（含用户原话） |
| **1.2 已决策事项** | 若是需求决策而非纯实现细节，补 `DC<下一个序号>` + 落点列（**最容易漏**） |
| **2.2 目标** | 若新能力改变"目标"，补编号条目（如"提供图形操作界面"） |
| **2.3 交付与部署约束** | 若新能力改变交付/使用形态（如"使用入口"），补一行 |
| **3.3 使用方式** | 代码块补调用示例 + 段落说明（若有新入口） |
| **5.1 功能总览** | 新增 `F<n>` 行（编号 / 优先级 / 平台相关性 / 里程碑） |
| 对应功能章节 | 如 F14.2 / F15 / F19 / F20 等，**编号子节**（F20.1~F20.6） |
| 6 / 7.1 / 7.2 | 非功能需求、技术选型、体积约束 |
| 7.3 目录树 + 架构约束表 | 新增 `internal/<pkg>/` 行；注意顺延 |
| 7.5 配置示例 / 7.5.1 校验规则 | 若涉及新配置字段 |
| 第 8 节交付物 | 新增/修订 D 编号（D1 本体、D5 README 常需同步） |
| 第 9 节验收 | 新增/扩展 A 编号；**里程碑里的 `A8~A3x` 与 `D1~D1x` 范围也要同步** |
| 第 10 节里程碑 | 新功能的 M 归属 + 该行末尾的范围声明 |
| 第 11 节风险表 | 新能力通常带来新风险（如"新界面破坏单文件形态"） |
| 第 12 节待确认项 | 关闭已定案的 Q，并补底部"已决策项"清单 |

**联动文档（同一轮必须一起改，否则文档互相打脸）**：

| 文档 | 必改内容 |
|------|----------|
| `README.md` | 首段引用文件名与版本、新增功能小节、参数表补新开关 |
| `docs/验收状态.md` | 标题里的版本号、`A1~A3x` 范围、新增能力验收行（含"未实测"行） |
| `docs/架构说明.md` | 包职责表补新包、实现取舍段补新机制 |
| `.workbuddy/memory/MEMORY.md` | 「权威文档」文件名、「当前文档状态」版本号与验收范围 |

### 第 3 步：grep 复核

```bash
cd "D:\workspace\AI\自动安装工具"
f=$(ls 自动安装工具prd-v*.md)
for k in "| C42 |" "| D17 |" "| 版本 | v2.13" "关键短语A" "关键短语B"; do
  printf "%-40s : %s\n" "$k" "$(grep -c -- "$k" "$f")"
done
# 表格行顺序也要看：
grep -n "^| C4[0-9] |" "$f" | cut -c1-16
```
任何一项为 0 = 没落表，重新执行该条编辑。**并行编辑同一文件极易互相回退，务必串行执行**。

### 第 4 步：升版本 + 重命名 + 提交（中文 message）

```bash
git mv "自动安装工具prd-vX.Y.md" "自动安装工具prd-vX.(Y+1).md"
git add -A && git commit -m "docs: PRD 升级 vX.(Y+1)，<一句话主题>

- <改动点1>
- <改动点2>
- 同步：变更记录 C4x；D1x；Ax；7.5 配置示例；文档版本升至 vX.(Y+1) 并重命名文件"
```

> 用户自定义指令：**每次改完都自动提交，commit message 用中文**；涉及云函数改动才需要上传部署（本 PRD 项目不涉及）。

### 第 5 步：追加工作日志

`D:\workspace\AI\自动安装工具\.workbuddy\memory\YYYY-MM-DD.md`（**append-only**），
按「标题 - 用户诉求 - 关键决策 - 同步落点 - 踩坑」结构追加，然后一并提交。

## 输出格式约定

- 面向用户回复时用**表格 + 小标题 + 具体数字**，把"改了什么/为什么/落在哪"讲清。
- 讲清**能力边界**：不要承诺工具做不到的事（如"安装完成"≠"软件可用"）。
- 结尾给出**下一步可拍板的点**（如"母版数量目标是否认可"），推动决策而非罗列。

## 项目背景速查

- 工具：Windows 离线沙箱「自动安装/触发」工具（Go 1.20.x、CGO_ENABLED=0 单文件、Win7 SP1+ 基线），
  目标 = **安装成功优先**，供 EDR 采集样本行为。
- 已定案：解压用外部 7-Zip（≥24.09，不降级不代装）；OCR 用外部 PaddleOCR-json（进程外调用）；
  GUI 三级识别 UIA→模板→OCR；判定口径 **宽松/宁可多报**（`judgment_profile: loose`）；
  单文件硬上限 600s；**单实例串行**调用（第二实例退出码 6）；跨平台扩展见 4.8；
  **图形操作界面**（F20 / DC21：双击 exe 或无参数独占新控制台即开界面，`--gui` 须单独使用；
  `internal/ui` 只用标准库 `syscall`、不引第三方 GUI 库；**界面只收集参数后调 `cli.Run`，不复制业务逻辑**）。
- 退出码：0 处理完成 / 1 工具异常或当前平台不支持 / 2 参数或输入非法 / 3 配置或资源错误 /
  4 缺 7-Zip / 5 要求 OCR 但不可用 / 6 单实例锁被占用 / 130 协作式中断。
  **退出码只表示工具自身状态，单文件结果只在结果 JSON**（F19.1）。
- 当前版本：**v2.16**；交付物 D1~D17；验收 **A1~A33**；已决策事项 DC1~DC22。

## 环境坑（本机特有，编译前必查）

- **`D:\Go` 被安天安全软件写入整份副本**：3358 个 `*.old.go`（覆盖 536 个目录），另有
  `*.old.md` / `LICENSE.old` 等。Go 把它们当作包的一部分，`go build` 会报
  `found packages X and X_test` 或 `import cycle not allowed`，**完全无法编译**。
  直接原因可在 `D:\AntiySafeDocBackup` 看到（2024-05-13 生成）。
- **绕过（不动原 GOROOT）**：另建干净 GOROOT —— `junction` 指向原 `bin`/`pkg`，
  再复制 `src` 并剔除 `*.old*`，最后用 `GOROOT=<新目录>` 编译。
  注意：删掉 `.old` 文件后**可能被安全软件重新生成**，属反复性环境问题。
- **`cmd //c "..."` 在本环境 Git Bash 里不生效**（cmd 会进入交互模式、命令静默丢失），
  需要 Windows 命令时改用原生终端工具执行。
- **跨平台编译卡点不要写 `go build -o /dev/null ./...`** —— `./...` 含多个包，会报
  `cannot write multiple packages to non-directory /dev/null`（且返回码仍是 0，**容易误判为通过**）。
  正确写法：`GOOS=linux GOARCH=amd64 go build ./...`（不带 `-o`），失败才非零退出。
- **PowerShell 工具里 `Start-Process -PassThru`（新建控制台）可用于真机冒烟**：
  `$p.Refresh(); $p.MainWindowTitle` 能直接读到窗口标题，`$p.HasExited` 判存活。
  但 **`-NoNewWindow -Wait -RedirectStandard*` 在本环境返回空结果**（`ExitCode`/文件长度全空），
  这类"共享控制台"用例改用 **Bash 工具直接执行 + 重定向**，退出码与产物都可靠。
  `Add-Type -MemberDefinition`（运行时编译 .NET）被安全策略**拦截**，枚举窗口请改用 `MainWindowTitle`。
- **验证 exe 冒烟要在干净临时目录做**（如 `/tmp/captest`），否则当前目录里既有的产物会干扰
  "是否留下垃圾文件"的判断。

## 界面实现坑（`internal/ui`，改动前必看）

- **只读 EDIT 控件发的是 `WM_CTLCOLORSTATIC`（0x0138），不是 `WM_CTLCOLOREDIT`（0x0133）**。
  父窗口若把所有 `WM_CTLCOLORSTATIC` 一并按 STATIC 标签处理（**透明背景 + `COLOR_3DFACE` 画刷**），
  多行日志区在**滚动 / 追加时旧字形不被擦除**，表现为**文字重影、互相覆盖**（v2.15 实测缺陷，C44）。
  正确做法：按**子控件句柄**区分，只读多行 EDIT 用**不透明背景（`OPAQUE`）+ `COLOR_WINDOW` 白底 +
  `COLOR_WINDOWTEXT` 文字**；该配色决策要抽成**纯函数**并写单测（`ctlColorScheme`），否则极易回归。
- **父窗口样式要带 `WS_CLIPCHILDREN`（0x02000000）**，否则窗口缩放/滚动时父窗口底色会盖到子控件区域。
- **多行 EDIT 只在 `CRLF`（`\r\n`）处折行**：日志用纯 `\n` 写入时**长行不换行、与上一行视觉粘连**，
  实测被用户描述成"日志没按时间换行"。修法：写入前统一做 `normalizeCRLF` 归一，并处理**分块边界**——
  上一段的末尾 `\r` 与本段开头的 `\n` 要合并成一个 CRLF（否则会在中间多出一个空行）；追加后用
  `EM_SCROLLCARET` 滚到末行。**这条与上一条（CTLCOLOR）是两个独立成因，别混为一谈**（C44 vs C45）。
- **下拉框**用 `COMBOBOX` + `CBS_DROPDOWNLIST`（`CB_ADDSTRING` / `CB_SETCURSEL` / `CB_GETCURSEL` /
  `CBN_SELCHANGE`）；下拉列表高度要单独设（`CB_SETITEMHEIGHT` 传 `-1`），否则高 DPI 下只露一行。
- **界面默认值可以与 CLI 不同，但必须"显式发出参数"**：本项目界面超时**预填 5 分钟**、CLI 默认 600 秒，
  界面**始终发 `--timeout <秒>`**，因此只是"预填值"差异、不产生歧义（DC22）。改这类默认值记得同步
  `docs/验收状态.md` 与 PRD 的 F20.2 / A33，并说明"CLI 默认值不变"。
- **给使用者看的结论文案要有表驱动单测**：本项目 `schema.OverallOutcome` 曾把 `installed` 与
  `unverified` 合并成一个"安装成功"档，结果日志同时出现「总体结论：安装成功」与「样本统计：…
  安装未验证 1」，被一眼看出矛盾。**语义强度不同的桶必须各自成档**（现为 `empty/ok/unverified/
  partial/failed/skipped`，见 F20.6），并用 `pkg/schema/result_test.go` 把档位与文案钉住。
- **代码注释引用的 PRD 小节号要真实存在**：曾出现注释里写着 `（F20.6）` 而 PRD 根本没有 F20.6
  （只到 F20.5）。改代码时若引用编号，顺手 `grep` 一下确认；没有就补一节，别让引用悬空。
- 界面的**视觉缺陷无法用单测覆盖**（`Add-Type` 截图被安全策略拦截，`PrintWindow` 方案成本高）：
  修完只能给出"根因 + 机制 + 待人工确认"的结论，并在 `docs/验收状态.md` 里如实标注
  "最终确认需人眼复核"，**不要写成"已实测通过"**。
