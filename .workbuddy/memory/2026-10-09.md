## 修正图形界面日志区「文字重影 / 互相覆盖」（PRD v2.14 → v2.15）

- **用户诉求**：实测反馈「运行日志区域滚动字体覆盖了」（此前一日刚交付 `internal/ui` 图形界面）。
- **根因（关键知识点）**：日志区是**只读**多行 EDIT，而 Windows 对**只读 EDIT 发送的是
  `WM_CTLCOLORSTATIC`（0x0138），不是 `WM_CTLCOLOREDIT`（0x0133）**。
  `form_windows.go` 的窗口过程把所有 `WM_CTLCOLORSTATIC` 连同 STATIC 标签一并处理成
  **透明背景（`SetBkMode(TRANSPARENT)`）+ `COLOR_3DFACE` 画刷**；控件绘制文字前不再擦除背景，
  于是滚动 / 追加日志时旧字形残留并与新文本叠加 → 视觉上「文字重影、互相覆盖」。
- **修法**：
  1. `handle()` 的 `wmCtlColorStatic/wmCtlColorBtn` 分支按**子控件句柄**（`lparam == f.ctrls[idLog]`）
     区分「日志区」与「标签/按钮」，日志区改用 **`OPAQUE` 背景 + `COLOR_WINDOW` 白底 +
     `COLOR_WINDOWTEXT` 文字**；
  2. 配色决策抽成**纯函数 `ctlColorScheme(isLog bool)`**，便于单测；
  3. 主窗口 `CreateWindowExW` 样式补 **`WS_CLIPCHILDREN`（0x02000000）**，父窗口重绘时跳过子控件区域，
     避免缩放 / 滚动时父底色盖到日志框；
  4. 新增常量 `colorWindowText = 8`、`opaqueBk = 2`、`wsClipChildren = 0x02000000`。
- **测试**：新增 `TestCtlColorSchemeKeepsLogOpaque`、`TestMainWindowStyleClipsChildren`
  （`internal/ui` 测试由 11 项增至 **13 项**；其中参数转换 8 项、Win32 相关 5 项）。
- **验证**：`gofmt`/`go vet` 为空；`go test ./...` 全绿；`GOOS=linux` / `GOOS=darwin`
  `go build ./...` 通过（A9 ③ 未回归）；重建 `dist/AutoTrigger.exe`（6,350,848 字节）后复测：
  双击开窗（标题 `AutoTrigger 图形界面 — 任意文件自动安装/触发工具  v0.1.0`）、
  无参数 + 重定向 → 退出 2 / stdout 0 字节 / 零产物、`--help` → 退出 0 / stdout 2900 字节。
  **滚动无重影只能人眼复核**（截图仍被安全策略拦截），已在 `docs/验收状态.md` 如实标注。
- **同步落点**：PRD 新增 **C44**（含根因与修法）、F20.2「日志」行补渲染硬约束、A33 ⑧ 补
  "滚动 / 追加无重影"卡点、版本行升 **v2.15** 并 `git mv` 重命名为 `自动安装工具prd-v2.15.md`；
  同步 `README.md`（引用文件名）、`docs/验收状态.md`（标题 v2.15 + GUI 测试项数修正 + 新增日志区渲染行）、
  `.workbuddy/memory/MEMORY.md`（权威文档文件名）、技能 `prd-version-iteration`（版本号 +
  新增「界面实现坑」小节 + 「纯实现缺陷也走 PRD 迭代流程」说明）。
- **踩坑 / 结论**：
  - **`CTLCOLORSTATIC` vs `CTLCOLOREDIT`** 是 Win32 里非常经典的坑：凡是"只读控件"或"复合控件里的
    只读子控件"都要单独确认它走哪条 `CTLCOLOR` 消息，否则背景/文字渲染会莫名其妙。
  - **PowerShell 工具里 `& $exe` 调用外部程序拿不到 `$LASTEXITCODE`、重定向文件也为空**
    （与既有的"-NoNewWindow -Wait -RedirectStandard* 返回空"同源）；命令行冒烟一律改用
    **Bash 工具 + 干净临时目录**，退出码与产物都可靠。
  - `Start-Process -PassThru`（新建控制台，即双击场景）仍可正常读 `MainWindowTitle` / `HasExited`，
    是验证"双击弹窗"最省事的手段；用完记得 `Stop-Process` 清理遗留界面进程。

## 界面日志友好化 + 结果彩色提示 + 两个下拉框（PRD v2.15 → v2.16）

- **用户诉求（原话）**："运行日志按时间合理换行，输出日志内容要友好，最好有中文，安装整个过程
  输出日志要清晰，安装成功失败要有明显的提示；超时输入框最好可以切换单位，默认是 5 分钟；
  日志级别最好是下拉框选项"。
- **两处用户决策**（AskUserQuestion）：① 超时默认 → **界面 5 分钟 / CLI 保持 600 秒**（刻意两档）；
  ② 结束提示 → **只做彩色横幅，不弹窗**。
- **改动要点**：
  1. **日志换行（真正的根因）**：多行 EDIT **只在 CRLF 折行**，日志写的是纯 `\n` → 长行不折、与上行粘连。
     新增 `normalizeCRLF(s, prevCR)` 归一，并处理**跨块 `\r` 边界**（上段末尾 `\r` + 本段开头 `\n`
     要合并为一个 CRLF）；追加后 `EM_SCROLLCARET` 滚到末行。**注意与 C44 的 CTLCOLOR 坑是两个独立成因**。
  2. **日志友好化**：行格式 `2006-01-02 15:04:05 [标签] 消息`；级别标签中文化 `[调试]/[信息]/[警告]/[错误]`；
     `Logger` 接口新增 `Stage(level, stage, format, args...)`；阶段前缀 `【任务】【识别】【入口】【执行】
     【判定】【结果】【清理】`；结束先打**结论行**再打统计摘要行（如 `样本统计：样本总数 1｜安装成功 1`）。
     `internal/logging` 重写；`engine/attempt/container/cli` 全量改中文 `Stage` 调用；
     `pkg/schema/result.go` 新增 `StatusText/BucketText/OverallOutcome/SummaryLine` 纯函数。
  3. **结果明显提示**：`internal/ui` 状态栏**加粗放大 + 语义色**（成功绿 / 失败红 / 部分成功或已中止橙 /
     运行中黑），日志末尾追加**彩色结论横幅**（`ResultBanner`，由退出码 + `summary` 推导），**不弹窗**；
     `WM_CTLCOLORSTATIC` 处理升级为**三角色**（日志白底不透明 / 状态语义色 / 标签透明 3D 面色）。
  4. **两个下拉框**：超时改【数值 + 单位下拉（分钟/秒）】、日志级别改 `COMBOBOX` 下拉。
  5. **超时默认两档**：`internal/ui/options.go` 界面预填 300s（`UITimeoutDefaultValue=5` + 单位分钟），
     `Args()` **始终显式发 `--timeout <秒>`**；CLI 默认仍 600s（DC20/DC17 未动）。
- **测试**：`internal/ui` 新增 `TestStatusColors`、`TestNormalizeCRLF`（7 例）、`TestDropdownOptionsAlign`，
  并把 `TestCtlColorSchemeKeepsLogOpaque` 改为三角色的 `TestCtlColorSchemeRoles`；
  `options_test` 新增 `TestTimeoutSeconds/TestSplitTimeout/TestResultBannerStatesOutcome/TestReadResultSummary`，
  `TestNewOptionsDefaultsMatchCLI` 改为断言 300s + 显式 `--timeout 300`。
- **踩坑**：
  - `finishStatus` 用到 `schema.Outcome*` 但 `form_windows.go` 未导入 `pkg/schema` → `undefined: schema`，补 import。
  - `d.Confidence` 是 **`*string`** 不是 float，直接 `%f` 打出 `%!f(*string=...)`，改为解引用后输出。
  - `TestNormalizeCRLF` "跨段 CR+LF" 期望写错：`normalizeCRLF("\n", true)` 的正确结果是 `\n`
    （前一段已写下配对 CRLF，本段只补 LF），改期望值而非改实现。
- **验证**：`gofmt`/`go vet` 为空；`go test ./...` 全绿；`GOOS=linux`/`GOOS=darwin` `go build ./...` 通过；
  重建 `dist/AutoTrigger.exe`（6,392,832 字节）；真机运行输出中文分级日志，末行 `样本统计：样本总数 1｜安装成功 1`；
  双击开窗正常（`Start-Process -PassThru`，pid 51096，已 `Stop-Process`）。**颜色观感仍需人眼复核**。
- **同步落点**：PRD 新增 **C45**（含两处根因与修法）与 **DC22**（超时两档默认例外）；版本行升 **v2.16** 并
