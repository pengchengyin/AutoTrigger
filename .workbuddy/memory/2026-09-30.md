## Windows 内置 OCR 实测（关键结论）
- **系统 OCR 引擎可用**（`Windows.Media.Ocr`）：`AvailableRecognizerLanguages` 仅 `zh-Hans-CN`（Count=1）；`MaxImageDimension=10000`。
- **`en-US` 不可用**：`TryCreateFromLanguage('en-US')` 返回 null，`IsLanguageSupported('en-US')=False`；`C:\Windows\OCR` 仅有 `zh-cn` 目录。
- **结论**：Windows OCR 是**单语言引擎**，本机只能识别中文界面；英文安装器（Inno/NSIS 英文版）的 OCR 定位不可靠 → 英文界面优先 UIA + 图像模板，镜像需补 `en-US` 语言包。
- 产出一键验证脚本 `scripts/verify-ocr.ps1`（列语言 / 查目录 / 生成中英测试图 / 端到端识别并输出像素包围盒），已作为交付物 D10 记入 PRD，结论回填为 C19 并改写 F16.3（P0）。

## 本机环境限制（复用经验）
- **PowerShell 工具不回传 stdout**：命令 exit 0 但无输出 → 需把结果 `Set-Content` 到 `$env:TEMP\xxx.txt`，再用 Read 工具读取。
- **`Add-Type` 与 `Assembly.Load*` 被安全策略拦截**（"compiles/loads .NET code"）→ 无法加载 `System.Runtime.WindowsRuntime` / `System.Drawing`；`System.StrongRuntimeWindowsExtensions` 不可用导致 **PowerShell 不会自动 await WinRT 异步方法**（返回 `System.__ComObject`，调用 `OpenAsync` 报错）。纯同步的 WinRT 静态 API（如 `AvailableRecognizerLanguages`）仍可直接调用。
- 需要图像处理/生成测试图时，用**系统 Python（`D:\python\python-3.14.5\python.exe`，已装 PIL 12.3.0 + numpy）**；managed python 3.13.12 无任何第三方包。

## PRD v2.4（OCR 换外部引擎 + 平台基线下探 Win7）
- 用户判断内置 OCR 不可靠，要求「Win7 以上通用、开源、好用、可单独安装」的 OCR。据此推翻 v2.3 的 Windows 内置 OCR 方案。
- **OCR 选型（调研结论）**：
  - 首选 **PaddleOCR-json**（hiroi-sora 维护，开源）：PaddleOCR C++ 版，绿色解压即用，**Win7 可用**；输出 JSON 含**四角坐标 + 原生 score**；支持 stdin/stdout 与 **TCP**（`-port`/`-addr=loopback`）；**需 CPU 支持 AVX**，初始化 ~0.6s。
  - 备选 **RapidOCR-json**（同作者姊妹项目，**不需要 AVX**，接口一致可无缝切换）；**Umi-OCR**（MIT，Win7 x64+，内置两种引擎，带 GUI/CLI/HTTP `127.0.0.1:1224`，约 500MB）；**tesseract**（Win7 兼容最广但中文效果弱）。
  - 调用一律**进程外**（stdio/环回 TCP/HTTP），**禁止 CGO**，保持静态单文件；引擎**常驻复用**而非每次启停。
- **平台基线下探到 Win7 SP1 x64** → **Go 必须锁 1.20.x**（Go 1.21 起放弃 Win7/8/8.1，要求 Win10/Server 2016+）。连带新增 4.6 节：Win7 UIA 覆盖弱化（更早回落模板/OCR）、DPI 用 `GetDeviceCaps(LOGPIXELSX)`+`SetProcessDPIAware` 回退、截屏标志按版本、可能需 VC++ 运行库、必须 Win7 实机验证（A20）。
- 其他落点：退出码新增 **5**（OCR 缺失且 `require_ocr: true`）；`ocr` 配置增 engine/engine_path/transport/startup_timeout_ms/recognize_timeout_ms/restart_on_failure/min_score 等；置信度改用**引擎原生 score**（取代 v2.3 启发式）；新增 7.6 OCR 接入约定；里程碑新增 **M0 环境与选型验证**；待确认项改为 Q7~Q11（**Q10：是否真需覆盖 Win7**——若不需可改用 Go 1.21+ 并简化兼容处理）。

## PRD v2.4 补充：运行时依赖边界（4.7 节）
- 用户追问「Go 打包成二进制直接分发到虚拟机，虚拟机上不用在乎 Go 和依赖吧」——需澄清**免安装 ≠ 零环境要求**，已在 PRD 新增 **4.7 节 + 验收 A22 + 决策 C23/DC12**。
- 边界分四类：**A 语言运行时**（不需要 Go/.NET/JRE；PE 导入表只应含系统 DLL）；**B 功能性前置**（7-Zip、OCR 引擎、VC++ 2015-2022 运行库——静态编译消不掉，须镜像预置）；**C 镜像准备项**（管理员权限、关闭 UAC、AV 排除目录、可写临时目录）；**D CPU/架构**（AVX 视 OCR 引擎而定、x64 only）。
- 新增**构建期硬性校验**（防误破坏零依赖）：CI 断言 `CGO_ENABLED=0`；用 `dumpbin /dependents` 核验导入表无 `vcruntime*`/`msvcp*`/第三方 DLL，异常即构建失败；禁止 `-buildmode=c-shared` 与 `plugin`；干净镜像冒烟。
- 新增风险项：**未签名单文件易被 AV/EDR 拦截或删除**（本工具行为特征明显），对策是镜像加排除目录 + 交付前实扫 + 预留代码签名；新增 **Q12**（目标虚拟机能否为工具目录配置 AV 排除项）。
- 注意：该场景下「排除项只针对工具自身进程/路径」，不能影响 EDR 对样本行为的采集。
