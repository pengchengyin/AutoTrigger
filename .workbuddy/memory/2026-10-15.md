# 2026-10-15 SSH 远程下发安装任务（测试虚拟机实测）

## 目标
向测试虚拟机（`administrator@172.25.5.40 -p44894`，win10 build 14393）下发
`Notepad3-Setup.exe`（Inno Setup 6.3，5,290,800 B，SHA-256 `053a0930…20b220f`）安装任务，
验证「SSH 提交 → 命名管道 → 桌面端执行」端到端是否成功。

## 结论
- **触发/识别链路达成目的**：样本被真实拉起，安装向导被自动点完（选择安装语言 → 下一步 → Accept →
  我同意此协议 → 下一步×3 → 安装），全程 `uia` 识别、无 UIPI 报错；产生了完整的进程/文件/注册表行为，
  EDR 可采集，OCR 引擎（PaddleOCR-json / RapidOCR-json）自检通过。
- **安装本身未完成**：安装阶段弹出 `Download failed` 对话框，点掉「确定」后安装进程不再有进展，
  结果 `final_status = killed_on_timeout`。6/9 次尝试：第 2/3/4 次 `idle_timeout`（≈77s），第 6 次 `deadline`（≈46.9s）。
  该字符串既不在样本二进制、也不在工具二进制中，判断为安装器的离线下载组件/外部组件；
  对话归属**按用户要求不再追查**。Notepad3 未落盘（无 `Program Files\Notepad3`、无卸载注册表项）。
- 两次提交的任务 ID：`73b4217050b14ac80ccc82c0f12ed13a`（未提权，失败）、
  `b09a8f11d5a9730bbc489a1098be800f`（已提权，killed_on_timeout）。

## 时间线 / 踩坑
1. **SSH 免交互**：本机无 `sshpass`，`paramiko` 装不上（沙箱断网）。改用 msys OpenSSH 10.3 的
   `SSH_ASKPASS=<脚本> SSH_ASKPASS_REQUIRE=force DISPLAY=`，可免交互密码登录。
2. **接收端未运行**：`task health` 报「接收端未开启/未运行」；接收端只在 GUI `show()` 时启动，
   `preferences.json: remote_tasks=true` 已开但没有自启项、进程不存在 ⇒ 需手动拉起桌面端。
3. **第一次提交失败（根因=未提权）**：桌面端以 Medium IL 运行（建计划任务时未给高权限令牌），
   Notepad3 安装器的「选择安装语言」窗口是 High IL，点击被 UIPI 拦截；
   结果 JSON 出现 `requires_elevation` 与 issues「建议以管理员身份运行」。静默 `/VERYSILENT` 1.5s 退出码 1。
4. **`schtasks /rl highest` 陷阱**：任务 XML 已写 `<RunLevel>HighestAvailable</RunLevel>`，
   但任务内 `whoami /groups` 仍是 `Medium Mandatory Level` —— 由非提权进程注册时该级别被静默降级。
5. **静默提权成功**：改「交互计划任务（InteractiveToken，能落 Console session 1）+ VBS 调
   `Shell.Application.ShellExecute(exe, "--gui", dir, "runas", 1)`」，探针实测 `High Mandatory Level`。
   该 VM `EnableLUA=1 / ConsentPromptBehaviorAdmin=0 / PromptOnSecureDesktop=0 / FilterAdministratorToken=1`，
   `AppInfo` 服务运行中 ⇒ 提权无弹窗。
6. **第二次提交**：GUI 自动化全通，仅卡在样本侧的 `Download failed`。
7. **收尾**：取消遗留诊断任务 `d794ca6ae1ed6271f8c8aa488650f466`，清理 VM 桌面 `at-*.txt/xml/json` 探针文件；
   VM 现处于「提权桌面端在跑 + 接收端 ok」状态。

## 补充：产品已加「开机自启」，但部署版本尚未包含
- 源码 `internal/ui/autostart_windows.go` 已实现自启：注册 `AutoTrigger-Logon-<hash>` 登录计划任务
  （LogonTrigger + InteractiveToken + `RunLevel=HighestAvailable`，动作 `<exe> --gui`），
  界面开关在设置基础设置区，文案「登录 Windows 后以管理员权限自动启动（保存后生效）」（`idAutoStart=5903`，
  位于 SSH 提交开关下方 `top+328`）；`requireStartupAdministrator()` 会在未提权时拒绝保存。
- 实测**部署版本还没有这个功能**：二进制里搜不到 `AutoTrigger-Logon-` 字符串 ——
  VM 上的 `AutoTrigger.exe` 以及本地 `dist/` 三个 preview 构建（20261014 / 20261014.2 / 20261015）均无。
  ⇒ 需用最新源码重新构建并部署，才能用自启替代临时提权脚本。
- 该自启是**登录触发**，依赖自动登录（VM 的 `AutoAdminLogon=1` 已具备）；首次启用仍需一次提权启动工具，
  因为保存自启设置本身要求已提权（且前面实测 `schtasks /rl highest` 由非提权进程注册会被降级）。
