# AutoTrigger 自动安装工具

AutoTrigger 是一款面向 Windows 的离线安装与文件触发工具，同时提供图形界面和命令行入口。只需把要处理的文件或文件夹交给它，它就会尝试静默安装、自动完成安装向导交互，并保存完整的执行日志与结果文件。全程本地运行，无需联网，也无需安装 Go。

## 1. 为什么选择 AutoTrigger

- **无人值守后台自动化**：在专用 Windows 主机或虚拟机上，配合自动登录、工具管理员自启和 SSH 接收，可在重启登录后自动就绪，远程上传安装包、提交任务并查询日志与结果，无需人员持续操作桌面。需要保持可交互桌面，非无桌面系统服务；部署清单见[无人值守 Windows 配置](docs/SSH远程任务说明.md#21-无人值守-windows-配置清单)。

- **一个工具，覆盖多种安装器**：内置对 Inno Setup、NSIS、MSI、WiX Burn 等常见安装器的适配，遇到特殊界面还可以用图像模板匹配来应对。
- **界面 + 命令行双入口**：普通用户用图形界面点选即可上手；自动化场景直接调用命令行，参数语义与输出契约保持稳定。
- **离线可用、开箱即用**：程序单文件运行，7-Zip 与 OCR 依赖可从随包的离线物料自动部署，不需要联网下载。
- **过程可见、结果可查**：实时执行日志、结构化结果 JSON、多档状态与证据，方便回溯每次安装到底发生了什么。
- **结果可信，有据可依**：安装判定基于证据分级、安装前后基线快照对比与反证据仲裁，并给出高/中/低置信度，明确区分“装成了 / 疑似装成 / 装了一半 / 本来就装着 / 没装成”。
- **智能超时，不误杀慢装**：采用活动感知超时（有进展就不计时），而不是简单掐表；超时后先优雅关闭、再清理进程树，并照常采集安装证据。
- **异常路径也有完整结果**：超时、中止、崩溃等场景同样写出可解析的完整结果 JSON，方便第三方脚本直接消费，无需人工解读。
- **可递归、可中止、可追溯**：支持文件夹递归与批量串行执行，支持协作式中止；每次任务独立保存日志与结果文件，任务历史可搜索、可回看。
- **模板可自建**：针对界面特殊的安装器，可以捕获截图制作图像模板并启用，让自动化覆盖更多真实场景。
- **支持远程提交**：可在同一 Windows 账户下通过 SSH 提交任务，安装与 OCR 仍在桌面端执行。

## 2. 测试效果

测试套件入口：[AutoTrigger-TestSuite](https://github.com/pengchengyin/AutoTrigger-TestSuite)。以下数据来自对原始结果 JSON 的只读核对，完整口径见[历史测试效果摘要](docs/历史测试效果摘要.md)。完整报告和套件的公开内容以该仓库实际发布为准。

**真实安装器测试**：管理员会话，Windows 10.0.26300 x64，工具 0.1.0 / Schema 2.8。01–05 组的 22 个真实安装器中，工具输出安装完成 **18 / 22（81.8%）**：

| 类别 | 输出安装完成 / 样本数 | 占比 | 其他结果及限制 |
|---|---|---|---|
| Inno Setup | 4 / 5 | 80.0% | 1 个部分完成；含安装后应用窗口拖至超时的情况。 |
| NSIS | 5 / 5 | 100.0% | 仅代表这 5 个已提权样本。 |
| MSI | 5 / 6 | 83.3% | 1 个部分完成，样本缺外部数据文件。 |
| WiX Burn | 2 / 3 | 66.7% | 1 个部分完成，涉及升级判定。 |
| 其他厂商安装器 | 2 / 3 | 66.7% | 1 个部分完成，涉及 GUI 等待。 |
| **合计** | **18 / 22** | **81.8%** | **其余 4 个为部分完成；不包含崩溃的压缩包组。** |

**稳定性与专项验证**：与上述安装统计分开看，不合并计算成功率。

| 验证项目 | 验证结果 | 边界 |
|---|---|---|
| 压缩包整组稳定性 | 从回调耗尽崩溃改善为 **1621 条结果正常收尾，约 38 分钟** | 含 1599 条跳过和解压子项，不是 1621 个软件安装成功；长耗时仍需优化。 |
| 合法文件误杀、黑名单与回滚保护 | 合法样本恢复执行；11 个陷阱无违规执行；回滚样本保留 6 条 N6 并判部分完成 | 针对性检查，不代表全部故障场景通过。 |
| 修复检查项汇总 | **7 项中 5 项完全通过、2 项部分通过/验证** | 活动感知及真实升级替换场景仍有待验证。 |

**图像模板同样能打**：除安装器自动识别外，图像模板也是一条可靠的自动化路径。自绘示例模板在 `v0.1.0-preview.20261014.2` 中通过[四图匹配测试](src/tools/package/templates_test.go)——只要针对目标界面制作并启用合格模板，就能稳定命中并完成交互。该项证据同样有效，但与安装器统计分开计算。

> 以上为历史构建的工具输出与验证证据，**不代表最新版整体成功率或所有软件的兼容率**；记录均标记 0.1.0，但不代表同一二进制。建议在专用虚拟机/快照中复测；任务结束或退出码为 0 不等于安装成功。

## 3. 快速开始

上手只需五步，图形界面对新手最友好：

1. **准备程序**：将交付包解压到可写目录，保留随包提供的依赖物料。运行工具本身不需要安装 Go。
2. **启动工具**：双击 `AutoTrigger.exe`。涉及系统级安装时，建议右键选择“以管理员身份运行”。
3. **检查环境**：在首页点击“检查环境”，确认 7-Zip 与 OCR 状态。缺失的依赖会尝试从本地离线包部署；工具不会联网下载。检测后优先保留当前可用 OCR，否则自动选择自检通过的引擎；没有未保存设置时自动保存，有修改时提示保存。主动禁用 OCR 时不会自动开启。
4. **执行任务**：点击“新建任务”，选择文件或文件夹并运行。公共执行参数在“设置”中统一配置。
5. **查看结果**：在任务列表打开“任务详情”，查看状态、实时执行日志和结果 JSON；可停止运行中的任务，或重新安装。

**结果判读**：任务结束或退出码为 0，不等同于安装成功，请结合任务详情中的状态、证据和日志确认。安装完成也不代表软件已激活或可正常使用。

**搭建无人值守执行主机**：推荐使用专用 Windows 10/11 虚拟机，配置指定账户自动登录、管理员权限自启、SSH 接收以及防止睡眠和空闲锁定，再做一次重启后的远程任务验收。具体步骤和安全注意事项见[SSH 远程任务说明](docs/SSH远程任务说明.md#2-主机准备)。自动登录等系统设置由部署人员配置；锁屏、UAC 安全桌面、安全软件拦截及安装器自身限制仍可能中断自动化，不代表任意软件都能全程无人干预安装。

结果结构、状态枚举和第三方对接注意事项见[结果 JSON 字段说明](docs/结果JSON字段说明.md)。

## 4. 数据与配置

在 **设置 → 基础设置** 中指定数据目录，默认位于 EXE 同级。各类数据按以下目录保存：

| 目录 | 内容 |
|---|---|
| `logs/` | 执行与环境检查日志 |
| `results/` | 任务结果 JSON 与恢复记录 |
| `templates/` | 模板、捕获图片和识别规则 |
| `third_parties/` | 7-Zip、OCR 离线包及部署文件 |
| `config/` | 配置文件、任务历史和界面偏好 |

配置文件为数据目录中的 `config/config.json`。修改数据目录并保存时，可选择复制迁移；原数据保留，目标已有数据不覆盖。EXE 同级的 `config/data-location.json` 用于记录数据目录位置，通常无需手动修改。

启动时不弹出旧版数据迁移提示，也不会自动迁移旧目录。需要沿用旧数据时，请先备份，再按当前目录约定手动整理。清理文件前，请确认不再需要其中的配置、模板或任务记录。

## 5. 模板管理

面对自绘界面或非标准安装器，模板就是提升成功率的利器：在“模板管理”中新建模板，进入详情捕获目标图片并标记动作，保存后勾选启用，后续任务即可自动匹配。制作方法见[图像模板制作说明](docs/图像模板制作说明.md)。

右上角支持批量 ZIP 导入、导出。导入不会覆盖同名模板，导入后需自行勾选启用；导出不携带启用状态。

离线交付 ZIP 自带“自绘安装向导（浅色示例）”，新解压的数据目录中默认启用，包含接受协议、下一步、安装和完成四个动作。仅适用于标题为“自绘界面安装向导 Synthetic”的浅色测试样本、96 DPI，不代表适配任意安装器。独立 EXE 不携带这套外部图片；升级时不要用交付包的 `templates/` 覆盖已有用户模板和启用索引。

## 6. 命令行使用

在程序所在目录打开 PowerShell，执行：

```powershell
.\AutoTrigger.exe --check-prereq --json
.\AutoTrigger.exe --input "D:\安装包\setup.exe" --output "D:\结果\result.json"
.\AutoTrigger.exe --help
```

只检测、不部署依赖时加 `--no-deploy-deps`；明确跳过 OCR 时加 `--no-ocr`。完整参数见 `--help`，配置字段说明可在设置的高级配置中查询。

**通过 SSH 提交任务**：主机安装 OpenSSH Server，并在已登录桌面的工具中勾选“设置 → 基础设置 → 允许通过 SSH 提交任务”，保存后生效。远程客户端使用同一 Windows 账户上传文件，再调用 `AutoTrigger.exe task submit`；安装和 OCR 仍在桌面端执行。具体步骤、命令与限制见[SSH 远程任务说明](docs/SSH远程任务说明.md)。

需要长期接收远程任务时，以管理员身份运行工具，在“设置 → 基础设置”勾选“登录 Windows 后以管理员权限自动启动”并保存。下次当前账户登录后，计划任务会启动 GUI；取消勾选并保存可关闭自启。此选项不会自动开启 SSH 接收，也不启用系统自动登录；用户未登录、锁屏或 UAC 安全桌面仍不能保证界面与 OCR 操作。请固定程序路径，移动前先关闭旧位置的自启。

## 7. 使用建议与注意事项

- **安全告警**：遇到 Defender 或其他安全软件拦截时，先暂停执行并核对来源及 SHA-256，不要反复恢复、关闭防护或直接加排除。保存检测名称、时间和保护历史供审查；可以向厂商提交样本复核，不能仅凭告警名称认定误报。本工具不保证所有安全产品均不告警。

- **权限确认**：UAC 提示需要核对程序来源后手动批准，工具不会自动绕过系统安全确认。
- **桌面状态**：锁屏及 UAC 安全桌面不能保证自动操作，执行 GUI 自动化时应保持可交互桌面。
- **休眠与计时**：测试期间建议关闭自动休眠。工具不会自动扣除采样中断时间，系统恢复后可能达到原超时上限；异常采样间隔会记录警告，不将其直接认定为睡眠。
- **提升成功率**：自动化效果受安装器界面、权限和前置条件影响。遇到界面特殊的安装器，建议先制作并启用图像模板再运行，可明显提高命中率。
- **兼容范围**：目标为 Windows 7 SP1 x64 及以上；Win7 实机兼容尚未完整验收。Windows 内置 OCR 当前未实现，已验证范围见[验收状态](docs/验收状态.md)。

## 8. 源码与构建

源码项目按 `src/`（Go 模块与开发工具）、`dist/`（本地运行与测试产物）、`docs/`（文档）组织。交付包中的程序位于包根目录。

安装 **Go 1.20.x** 后，在项目根目录的 PowerShell 中执行以下命令，完成测试与构建：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\src\scripts\build.ps1
```

Go 不在 PATH 中时，在命令末尾加 `-Go "D:\gc3\bin\go.exe"`，替换为实际路径。构建成功后生成 `dist/AutoTrigger.exe`。

更多技术信息参见[架构说明](docs/架构说明.md)和[图像模板制作说明](docs/图像模板制作说明.md)。
