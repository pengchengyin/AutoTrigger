# AutoTrigger 自动安装工具

AutoTrigger 是面向 Windows 环境的离线安装与文件触发工具，提供图形界面和命令行入口。可处理单个文件或文件夹，尝试静默安装及安装向导自动操作，并保存执行日志与结果文件。

## 1. 快速开始

1. **准备程序**：将交付包解压到可写目录，保留随包提供的依赖物料。运行工具本身不需要安装 Go。
2. **启动工具**：双击 `AutoTrigger.exe`。涉及系统级安装时，建议右键选择“以管理员身份运行”。
3. **检查环境**：在首页点击“检查环境”，确认 7-Zip 与 OCR 状态。缺失的依赖会尝试从本地离线包部署；工具不会联网下载。
4. **执行任务**：点击“新建任务”，选择文件或文件夹并运行。公共执行参数在“设置”中统一配置。
5. **查看结果**：在任务列表打开“任务详情”，查看状态、实时执行日志和结果 JSON；可停止运行中的任务，或重新安装。

**结果判读**：任务结束或退出码为 0，不等同于安装成功，请结合任务详情中的状态、证据和日志确认。安装完成也不代表软件已激活或可正常使用。

结果结构、状态枚举和第三方对接注意事项见[结果 JSON 字段说明](docs/结果JSON字段说明.md)。

## 2. 数据与配置

在 **设置 → 基础设置** 中指定数据目录，默认位于 EXE 同级。各类数据按以下目录保存：

| 目录 | 内容 |
|---|---|
| `logs/` | 执行与环境检查日志 |
| `results/` | 任务结果 JSON 与恢复记录 |
| `templates/` | 模板、捕获图片和识别规则 |
| `third_parties/` | 7-Zip、OCR 离线包及部署文件 |
| `config/` | 配置文件、任务历史和界面偏好 |

配置文件为数据目录中的 `config/config.json`。修改数据目录并保存时，可选择复制迁移；原数据保留，目标已有数据不覆盖。EXE 同级的 `config/data-location.json` 用于记录数据目录位置，通常无需手动修改。

启动时不弹出旧版数据迁移提示，也不会自动迁移旧目录。需要沿用旧数据时，请先备份，再按当前目录约定手动整理。清理文件前，请确认不再需要其中的配置、模板或任务记录。

## 3. 模板管理

在“模板管理”中新建模板，进入详情捕获目标图片并标记动作，保存后勾选启用，供后续任务匹配。

右上角支持批量 ZIP 导入、导出。导入不会覆盖同名模板，导入后需自行勾选启用；导出不携带启用状态。

离线交付 ZIP 自带“自绘安装向导（浅色示例）”，新解压的数据目录中默认启用，包含接受协议、下一步、安装和完成四个动作。仅适用于标题为“自绘界面安装向导 Synthetic”的浅色测试样本、96 DPI，不代表适配任意安装器。独立 EXE 不携带这套外部图片；升级时不要用交付包的 `templates/` 覆盖已有用户模板和启用索引。

## 4. 命令行使用

在程序所在目录打开 PowerShell，执行：

```powershell
.\AutoTrigger.exe --check-prereq --json
.\AutoTrigger.exe --input "D:\安装包\setup.exe" --output "D:\结果\result.json"
.\AutoTrigger.exe --help
```

只检测、不部署依赖时加 `--no-deploy-deps`；明确跳过 OCR 时加 `--no-ocr`。完整参数见 `--help`，配置字段说明可在设置的高级配置中查询。

**通过 SSH 提交任务**：主机安装 OpenSSH Server，并在已登录桌面的工具中勾选“设置 → 基础设置 → 允许通过 SSH 提交任务”，保存后生效。远程客户端使用同一 Windows 账户上传文件，再调用 `AutoTrigger.exe task submit`；安装和 OCR 仍在桌面端执行。具体步骤、命令与限制见[SSH 远程任务说明](docs/SSH远程任务说明.md)。

## 5. 使用注意事项

- **权限确认**：UAC 提示需要核对程序来源后手动批准，工具不会自动绕过系统安全确认。
- **桌面状态**：锁屏及 UAC 安全桌面不能保证自动操作，执行 GUI 自动化时应保持可交互桌面。
- **能力边界**：自动化效果受安装器界面、权限和前置条件影响，不保证所有安装包均能无人值守完成。
- **兼容范围**：目标为 Windows 7 SP1 x64 及以上；Win7 实机兼容尚未完整验收。Windows 内置 OCR 当前未实现，已验证范围见[验收状态](docs/验收状态.md)。

<details>
<summary>受控测试环境的 UAC 设置（可选）</summary>

不建议在日常电脑关闭 UAC 通知。仅在具备管理权限的受控测试机操作：

1. 在开始菜单搜索“更改用户账户控制设置”，记录当前滑块位置。
2. 选择“从不通知”，点击确定并批准权限请求；按系统提示重启。
3. 测试结束后恢复原位置。

此操作会降低安全防护，不代替管理员权限，也不保证所有安装器能够无人值守。工具不会自动修改 UAC 设置。

## 6. 源码与构建

源码项目按 `src/`（Go 模块与开发工具）、`dist/`（本地运行与测试产物）、`docs/`（文档）组织。交付包中的程序位于包根目录。

安装 **Go 1.20.x** 后，在项目根目录的 PowerShell 中执行以下命令，完成测试与构建：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\src\scripts\build.ps1
```

Go 不在 PATH 中时，在命令末尾加 `-Go "D:\gc3\bin\go.exe"`，替换为实际路径。构建成功后生成 `dist/AutoTrigger.exe`。

更多技术信息参见[架构说明](docs/架构说明.md)和[图像模板制作说明](docs/图像模板制作说明.md)。
