# 图像模板制作说明

> **对应需求**：F14.2（模板覆盖与变体）、F14.7（内置资源包）、F14.5（DPI 换算）
> **对应交付物**：D3（内置资源包）、D17（本文档）
> **读者**：模板制作者 / 交付工程师 / 现场补模板的运维
> **一句话**：把"安装向导上的一个按钮"变成一张能被工具稳定命中的模板图。

---

## 1. 快速上手（TL;DR）

当前版本的内置图像索引仍为空，内置关键词与规则不等于按钮图片；图像覆盖以实际模板管理列表为准。本文档用于两类场景：
**(a) 构建内置模板包**（发版前的标准动作）；**(b) 现场补模板**（遇到内置模板命中不了的安装器）。

### GUI 制作入口

打开 **模板管理 → 制作模板**：

1. 填写模板名称，点击“新建模板”。下拉框可以切换多个模板项目，各自保存多张图片。
2. 自行打开真实安装器，停在目标页面。点击“屏幕框选”，工具自动隐藏，直接在任意已打开画面或弹窗中拖动框选按钮，松开鼠标返回。Esc 或右键取消；不必选择进程、刷新窗口或再次点击抓图。也可载入原始 PNG。
3. 选择按钮动作，按需调整安装器家族、语言、DPI、主题和坐标，点击“保存图片”。默认字段可直接沿用，ID 自动生成；图片尺寸仍遵循按钮模板规范 24~240 × 16~48 像素。继续截图可保存多个按钮，图片列表支持预览和删除。
4. 保存只更新草稿，不影响执行。准备完成后点击“发布”，自动校验源截图，生成独立发布素材并保存 CLI 的既有模板配置，后续任务自动匹配已发布图片，无需每次手动选择模板。发布多个项目会合并，不相互覆盖。
5. 编辑已发布模板不会改变当前发布版本，需再次点击“发布”；“取消发布”从执行索引移除该项目，保留草稿与素材。删除草稿图片也需要再次发布才影响执行。自检仅证明源截图匹配，仍需在真实安装器上验证命中。

草稿保存在工具同级 `template-projects`，执行索引及不可变发布素材保存在当前配置的模板目录。截图只写入本机；注意不要采集含敏感信息的屏幕。发布使用合并模式，并保留已有自定义模板及配置中的其他字段。

GUI 保存的是当前实际截图档位，不自动伪造其他语言、主题或 DPI 图片。非标准 DPI 窗口需先调整到支持档位。首次采集建议 100% DPI、浅色主题；深色和 Win7 经典主题需核对实际外观。

### 命令行制作流程

三步：

```bat
:: ① 拿到现场素材：截窗口 + UIA 树 + OCR 结果
AutoTrigger.exe --dump-ui --input sample.exe --out dump\20260930_1600

:: ② 从 dump 里裁出控件小图，按规范命名后放进 masters\
::    （手工步骤，见第 4、5 节）

:: ③ 生成变体 + 索引，并自校验
tools\template-gen.exe --masters masters\ --out assets\builtin\templates
AutoTrigger.exe --self-test templates
```

第 ③ 步**任一张模板匹配失败即视为失败**，必须修掉再入库（F14.2）。

## 2. 前置准备

### 2.1 采集环境（关键，决定模板可用性）

同一按钮在不同环境下的像素外观不同，**模板必须在正确的环境里采集**：

| 环境项 | 采集要求 |
|--------|---------|
| **DPI 缩放** | 母版统一在 **100%** 采集；其余档位（125/150/200%）由 `template-gen` 生成 |
| **系统主题** | 母版统一在 **浅色主题** 采集；深色主题变体由 `template-gen` 生成 |
| **系统语言** | **zh-CN 与 en-US 各截一遍**（字形宽度不同，不能互转） |
| **系统版本** | Win10/11 采集母版；**Win7 经典主题档位**单独采集或用 `template-gen` 合成 |
| **安装器版本** | 优先采集**主流稳定版**，新旧差异大时记录版本号进模板备注 |

> ⚠️ **不要**在缩放非 100%、非浅色主题的机器上截母版 —— 母版是基准态，混入其它档位会让整套变体生成错位。

### 2.2 需要的工具

| 工具 | 用途 |
|------|------|
| `AutoTrigger.exe` | `--dump-ui` 取素材、`--self-test templates` 自校验、`--dump-resources` 导出内置资源 |
| `tools/template-gen` | 母版 → 变体批量生成 + 写索引（构建期工具） |
| 截图/看图工具 | 手工裁剪母版（推荐支持像素级框选的工具） |
| 7-Zip | 解包安装器，用于**单独启动安装向导**便于反复取图 |

### 2.3 取图思路

模板采集**不需要真的把软件装完**。推荐做法：

1. 用 7-Zip 解开安装器，或直接启动安装器；
2. 让安装向导停在**目标按钮可见**的那一页（例如"下一步"页、"我接受"页）；
3. `--dump-ui` 抓图；
4. 反复取图时**不要点击推进**，用取消/关闭退出后重新启动。

## 3. 采集：用 `--dump-ui` 拿素材

```bat
AutoTrigger.exe --dump-ui --input <样本或安装器> --out dump\<时间戳>
```

输出结构：

```
dump\20260930_1600\
├─ screenshots\win_0001.png      # 原始窗口截图（按发现顺序编号）
├─ uia\win_0001.json             # UIA 控件树：控件名 / 类型 / 屏幕矩形
├─ ocr\win_0001.json             # OCR 结果：文本 + 四角坐标 + score
├─ shots\failed_*.png            # 若开启 dump_failed_shots，则含识别失败现场
└─ manifest.json                 # 汇总：窗口标题、进程名、DPI、主题、时间
```

**怎么用这三份数据配合裁图**：

| 数据源 | 用途 |
|--------|------|
| `uia\*.json` | 直接给出控件的**精确矩形**，优先按它裁（最准） |
| `ocr\*.json` | UIA 拿不到时（自绘界面），按文本 + 四角坐标定位按钮区域 |
| `screenshots\*.png` | 裁剪的像素来源 |
| `manifest.json` | 记录 DPI / 主题，确认素材是在 100% + 浅色下采的 |

> 若 `manifest.json` 显示 `dpi != 100` 或 `theme != light`，**这批素材只能用作参考，不能作为母版**。

## 4. 裁剪母版（最容易出错的一步）

### 4.1 硬性规则

| 规则 | 要求 |
|------|------|
| **只裁控件本体** | 只含按钮/复选框/图标本身，**不含周围背景、窗口边框、相邻控件** |
| **紧贴外接矩形** | 从控件边界裁，不留内边距（留边会让匹配对位置敏感） |
| **灰度化** | 统一 8-bit 灰度（工具运行时也按灰度匹配，**彩色模板会被拒**） |
| **尺寸区间** | 宽 **24~240 px**、高 **16~48 px**；过小无区分度、过大易误匹配 |
| **不裁动态内容** | 含进度百分比、倒计时、用户名的按钮**一律不裁**（每帧都在变） |
| **不改内容** | **禁止**手动重绘、加边框、锐化、加文字 —— 只要像素级还原 |

### 4.2 该裁 vs 不该裁

| ✅ 该裁 | ❌ 不该裁 |
|--------|----------|
| "下一步" / "Next" 按钮本体 | 整行按钮栏（含多个按钮 + 空白） |
| "我接受协议"复选框（**未勾选态**） | 带进度文字的"安装中 45%"按钮 |
| "浏览…"按钮、"×"关闭按钮 | 窗口整体截图 |
| 路径输入框（**空态**） | 已经填入具体路径的输入框 |

### 4.3 状态要分张

同一控件不同状态**必须分成独立模板**，不能只存一张：

| 控件 | 需要的张数 |
|------|-----------|
| 复选框 | **未勾选 / 已勾选** 各 1 张 |
| 按钮 | **可用态 / 禁用态（灰化）** 各 1 张（禁用态仅作参考，不点击） |
| 标签页 | 选中态 1 张（用于判断当前步骤） |

命名上用 action 后缀区分：`checkbox_off` / `checkbox_on`、`install` / `install_disabled`。

### 4.4 裁剪自检

裁完先自己看一遍：

- [ ] 灰度图，无彩色残留
- [ ] 四周紧贴控件，无多余背景
- [ ] 长宽在 24~240 × 16~48 区间
- [ ] 无动态文本（百分比、时间、用户名）
- [ ] 按钮文字清晰、无压缩伪影（PNG 无损保存）
- [ ] 同一家族按钮风格一致（确认没混入别家安装器的图）

## 5. 命名与目录规范

### 5.1 命名格式

```
<family>__<action>__<lang>__<dpi>__<theme>.png
```

例：`inno__install__zh-CN__100__light.png`

字段之间用**双下划线 `__`** 分隔（family / action 内部允许出现单下划线）。

| 字段 | 取值 | 说明 |
|------|------|------|
| `family` | 见 5.2 表 | 安装器家族，小写 |
| `action` | 见 5.2 表 | 控件语义，小写 |
| `lang` | `zh-CN` / `en-US` | 界面语言 |
| `dpi` | `100` / `125` / `150` / `200` | 母版固定 `100` |
| `theme` | `light` / `dark` / `win7classic` | 母版固定 `light` |

### 5.2 取值枚举

**family**

| 值 | 安装器 |
|----|--------|
| `inno` | Inno Setup |
| `nsis` | NSIS |
| `installshield` | InstallShield |
| `msi` | Windows Installer 标准 UI |
| `wixburn` | WiX Burn |
| `advinstaller` | Advanced Installer |
| `installaware` | InstallAware |
| `setupfactory` | Setup Factory |
| `wise` | Wise Installation Studio |
| `smartinstall` | Smart Install Maker |
| `electron` | Electron / CEF 自绘安装器 |
| `gamelauncher` | 游戏启动器型安装器 |
| `common` | 跨家族通用控件 |

**action**

| 值 | 语义 | 是否点击 |
|----|------|---------|
| `next` | 下一步 | 是 |
| `install` | 安装 | 是 |
| `accept` | 我接受（协议） | 是 |
| `finish` | 完成 | 是 |
| `yes` / `ok` | 是 / 确定 | 是 |
| `browse` | 浏览… | 是 |
| `close` | 关闭（×） | 是 |
| `checkbox_off` / `checkbox_on` | 复选框未勾选 / 已勾选 | 勾选 |
| `pathinput` | 路径输入框 | 输入 |
| `dropdown` | 下拉框箭头 | 展开 |
| `cancel` / `uninstall` / `no` | 取消 / 卸载 / 否 | **否（黑名单，仅记录）** |

### 5.3 目录结构

```
masters\                          # 母版：人工维护，唯一手工维护的目录
├─ inno\
│   ├─ inno__next__zh-CN__100__light.png
│   └─ inno__next__en-US__100__light.png
├─ nsis\
└─ common\

assets\builtin\templates\         # 变体：template-gen 生成，不手工改
├─ inno\
│   └─ inno__next__zh-CN__125__dark.png
└─ templates.index.json           # 索引：运行时按 DPI/主题/语言按需加载
```

> **铁律**：`masters\` 手工维护，`assets\builtin\templates\` **只由工具生成**。任何对生成目录的手改都会在下次构建时被覆盖。

## 6. 生成变体（不要手工做）

```bat
tools\template-gen.exe --masters masters\ --out assets\builtin\templates
```

生成逻辑：

| 输入（母版） | 展开为 |
|-------------|--------|
| `family__action__lang__100__light.png` | 4 DPI（100/125/150/200）× 3 主题（light/dark/win7classic）= **12 个组合** |

- **DPI 变体**：按比例重采样（100→125/150/200），使用与运行时一致的插值算法；
- **主题变体**：深色主题做背景替换与对比度适配；Win7 经典按边框/渐变差异合成；
- **去重**：同一母版的各变体两两比对，**SSIM > 0.98 视为等价并合并**（例如某些按钮在灰度化后浅色/深色几乎一致）—— 这是"50 张母版展开后实际落在 180~300 张"的原因；
- **写索引**：输出 `templates.index.json`，运行时**只加载匹配当前档位的文件**，不全量载入。

体积预算：全部模板资源 **≤ 8 MB**（灰度 + 裁到外接矩形 + PNG 量化后），与 7.2 的 exe ≤ 30 MB 一致。

## 7. 自校验与入库

```bat
AutoTrigger.exe --self-test templates
```

**校验规则**：每张模板必须能在**它自己的源截图**上匹配成功。

| 结果 | 含义 | 处理 |
|------|------|------|
| 全部通过 | 模板可用于匹配 | 入库 |
| 某张失败 | 死模板（塞进去了但永远匹配不上） | **构建失败**，必须修 |

常见失败原因与修法：

| 现象 | 原因 | 修法 |
|------|------|------|
| 匹配 0 命中 | 模板不是灰度图 | 转 8-bit 灰度后重新生成 |
| 命中位置偏移 | 模板含多余背景，边缘与截图不一致 | 重新紧贴控件裁 |
| 相似度刚好卡在阈值下 | 模板有压缩伪影 / 缩放失真 | 用无损 PNG 重新裁 |
| 多张互相抢命中 | 两张模板过于相似（如 zh/en 裁重了） | 检查命名与归属，去重 |

阈值默认 `gui_automation.template_min_similarity = 0.86`；自校验用**同源截图**，理应远高于阈值，低于 `0.95` 就要怀疑模板质量。

## 8. 覆盖内置 / 现场补充

### 8.1 拿内置资源做起点

```bat
AutoTrigger.exe --dump-resources .\myres
```

把内置模板与规则表导出到磁盘，**作为修改起点**：改完放回 `templates\` 即生效，**无需重新发版**。

### 8.2 合并语义（F14.7）

| `gui_automation.template_pack` | 行为 |
|-------------------------------|------|
| `merged`（默认） | 内置为底 + 外部为增量；外部**按 ID 覆盖**同名内置项 |
| `builtin` | 只用内置（排障：确认问题是否由外部模板引起） |
| `external` | 只用外部（严格复现某个已知环境） |

- 外部 `templates\` **只需写差异项**，不必复制整套内置模板；
- `builtin_templates: false` 可整体停用内置模板，**且不报错**（用于纯 OCR 模式排障）。

### 8.3 现场补模板的典型流程

```bat
:: 1. 复现问题，保留现场
::    临时把 config.json 的 gui_automation.dump_failed_shots 设为 true
AutoTrigger.exe --input unknown_setup.exe --output result.json

:: 2. 从 shots\failed_*.png 找到按钮，裁成母版
:: 3. 按规范命名，放进 templates\<family>\
:: 4. 只跑自校验（不必重新生成变体）
AutoTrigger.exe --self-test templates
```

## 10. 验收清单

入库前逐项打勾：

- [ ] 母版在 **100% DPI + 浅色主题** 环境采集（`manifest.json` 可证）
- [ ] zh-CN / en-US **双语齐全**（不得只做中文）
- [ ] 模板为灰度图，紧贴控件外接矩形，尺寸在 24~240 × 16~48
- [ ] 无动态文本、无手工重绘、无损保存
- [ ] 复选框**勾选/未勾选分张**
- [ ] 命名符合 `<family>__<action>__<lang>__<dpi>__<theme>.png`
- [ ] `template-gen` 生成成功，`templates.index.json` 已更新
- [ ] `--self-test templates` **全部通过**（含新增项）
- [ ] 模板资源总量 **≤ 8 MB**
- [ ] 至少在一个**真实安装器**上端到端验证命中（不只看自校验）
- [ ] 新增/变更的 family 已在本文档 5.2 表中登记

## 11. 常见问题（FAQ）

| 问题 | 答案 |
|------|------|
| 能不能直接截整行按钮栏？ | 不能。整行含空白与相邻控件，匹配会因位置敏感而失败 |
| 中文模板能当英文用吗？ | 不能。字形宽度不同，必须分别采集 |
| 深色主题下按钮不一样，要重新采集吗？ | 不需要手工采集，`template-gen` 从母版生成 |
| Win7 上没机器，Win7 档位怎么办？ | 优先真实采集；无法采集时用 `template-gen` 按边框/渐变差异合成，并在模板备注标注来源 |
| 模板越多越好吗？ | 不是。过多相似模板会互相抢命中并拖慢匹配，**相似项应去重** |
| 自校验过了但现场还是不命中？ | 检查现场 DPI/主题/语言是否落在变体覆盖内；若超出（如 175% 非标缩放），需补充该档位 |
| 自绘安装器完全没模板能识别吗？ | 可以。GUI 三级识别为 UIA → 模板 → **OCR**，模板缺失时由 OCR + 关键词表兜底 |
| 模板会随工具版本更新吗？ | 会，但版本解耦。`resource_pack_version` 单独输出在 `--version` / `--capabilities --json` / 结果 JSON 中，便于确认模板是否已更新 |

## 12. 附录：索引字段说明

`templates.index.json`（节选）：

```json
{
  "resource_pack_version": "1.0.0",
  "entries": [
    {
      "id": "inno__install__zh-CN__100__light",
      "family": "inno",
      "action": "install",
      "lang": "zh-CN",
      "dpi": 100,
      "theme": "light",
      "file": "inno/inno__install__zh-CN__100__light.png",
      "width": 88,
      "height": 26,
      "source": "builtin"
    }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `id` | 模板唯一标识，**外部覆盖内置即按此 ID 匹配** |
| `source` | `builtin`（内置）/ `external`（外部覆盖） |
| `dpi` / `theme` / `lang` | 运行时按当前环境**只加载匹配档位** |
| `width` / `height` | 匹配时用于快速剔除尺寸不符的候选（加速） |
